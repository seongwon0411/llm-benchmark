# 보안 검토 리포트

## 1. SQL 인젝션 취약점 (심각도: 높음)
- **시나리오**: `user` 또는 `password` 파라미터에 malicious한 SQL을 입력하면 쿼리가 조작됨.
  예: `user=' OR '1'='1`로 로그인 시 관리자 권한 획득 가능
- **수정 방향**: 파라메터화된 쿼리 사용 (예: `conn.execute("SELECT role FROM users WHERE name=? AND password=?", (user, password))`)

## 2. 평문 비밀번호 저장 (심각도: 높음)
- **시나리오**: 코드 내부에 `PASSWORD = "admin123"`처럼 암호가 노출됨.
  예: 코드베이스 유출 시 즉시 공격자에게 정보 제공
- **수정 방향**: 환경변수 또는 암호화된 저장소 사용 (예: `os.getenv('DB_PASSWORD')`)

## 3. 입력 검증 부재 (심각도: 중간)
- **시나리오**: 특수문자나 길이 초과 입력에 대한 처리 없음.
  예: SQL 인젝션 또는 시스템 오류 유발 가능
- **수정 방향**: 입력값에 대해 정규식 검증 및 길이 제한 추가

## 4. 로그 업데이트 쿼리 취약점 (심각도: 중간)
- **시나리오**: `audit` 테이블 업데이트 시 SQL 인젝션 가능성 있음.
  예: `user` 값에 `'; DROP TABLE audit;--` 입력 시 데이터 손실
- **수정 방향**: 파라메터화된 쿼리로 변경 및 로그 기록 로직 분리
