# 개정 표준 운영 절차 (SOP)

## 1. 목적
감사 지적 사항 개선 및 정책 준수를 위한 변경 관리 프로세스 수립

## 2. 핵심 원칙
- ✅ 모든 변경은 티켓 번호 기반 문서화 필수
- 🚫 작업자/승인자 역할 분리 (동일 인원 금지)
- 💾 실행 전 백업 및 복구 테스트 확인 의무
- ⏳ 실패 시 즉시 롤백, 24시간 내 사후 승인 요건

## 3. 일반 변경 절차 (체크리스트)
1. **변경 요청**
   - [ ] 티켓 생성 (예: T-20231001-001)
   - [ ] 작업자 → 승인자(팀장) 서면 승인 요청
2. **준비 단계**
   - [ ] 변경 전 백업 수행 (백업 ID 기록)
   - [ ] 복구 테스트 성공 확인
3. **실행 단계**
   - [ ] 승인자와 작업자가 다른 인원이어야 함
   - [ ] 변경 내역 시스템에 기록
4. **모니터링**
   - [ ] 24시간 동안 이상 유무 점검

## 4. 긴급 변경 절차
1. **즉시 조치** (24시간 이내)
   - [ ] 티켓 생성 + "긴급" 태그 추가
   - [ ] 승인자 서면 승인 후 변경 수행
2. **사후 처리**
   - [ ] 24시간 내 사후 승인서 제출
   - [ ] 롤백 기준: 시스템 다운타임 ≥ 10분 또는 데이터 손실 발생

## 5. 롤백 프로세스
| 조건 | 책임자 | 절차 |
|------|--------|------|
| 실패 감지 | 작업자 | 즉시 원본 복구 |
| 사후 승인 거부 | 승인자 | 변경 무효화 처리 |
