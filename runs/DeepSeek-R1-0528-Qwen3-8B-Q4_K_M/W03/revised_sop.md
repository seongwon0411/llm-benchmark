# Revised SOP Checklist

## Current Steps (Revised)
1. 변경 요청 티켓 생성 및 기록화: 모든 변경은 티켓 번호 필요
   - Takeaway: 변경 요청 시 반드시 티켓을 생성하고, 이력을 문서화합니다.
2. 승인자와 작업자의 분리: 일반 변경은 작업자와 승인자를 명확히 구분
   - Takeaway: 동일인이 승인과 실행을 담당하지 않도록 합니다.
3. 사전 백업 및 복구 테스트 확인: 변경 전에 백업과 복구 가능성을 검증합니다
   - Takeaway: 변경 작업 시작 전 반드시 백업 상태와 복구 절차를 문서화합니다.
4. 실패 기준 춀족 시 즉시 롤백: 문제가 발생하면 정해진 기준에 따라 신속히 롤백
   - Takeaway: 변경 실패 시 지연 없이 규정된 절차로 롤백을 수행합니다.
5. 긴급변경 사후승인: 긴급 변경은 우선 처리되나 24시간 내 승인 확인 필요

## Audit Findings
### L1 감사 지적
- Takeaway: 모든 변경 절차는 문서화되고 허가를 받았어야 합니다.

### L2 변경 요청 기록이 남지 않음
- 해결책: 변경 요청 시 반드시 티켓 생성

### L3 승인자와 작업자가 동일한 사례 존재
- 해결책: 승인과 실행을 다른 사람에게 맡깁니다.

### L4 사전 백업 확인 증적 없음
- 해결책: 변경 전에 반드시 백업 확인 테스트를 합니다.

### L5 롤백 기준과 책임자 불명확
- 해결책: 정해진 롤백 기준을 문서화하고, 책임자를 명시합니다.

### L6 긴급변경 사후승인 기한이 없음
- 해결책: 24시간 내 승인 확인 절차를 추가합니다.
