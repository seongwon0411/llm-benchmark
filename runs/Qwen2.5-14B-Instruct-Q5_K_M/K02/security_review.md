# Security Review

## 문제 1: 하드코딩된 비밀번호
- **Severity:** High
- **시나리오:** 악의적인 사용자가 소스 코드에 접근하면, 하드코딩된 비밀번호 `admin123`을 쉽게 알아낼 수 있습니다.
- **수정 방향:** 환경 변수를 통해 비밀번호를 관리하거나, 보안 설정 파일에서 비밀번호를 읽어오는 방법을 사용해야 합니다.

## 문제 2: SQL 인젝션 취약점
- **Severity:** High
- **시나리오:** `login` 함수 내부의 SQL 쿼리는 직접 문자열 연결을 통해 동적 생성되며, 이는 SQL 인젝션 공격에 노출될 수 있습니다.
- **수정 방향:** 파라미터화된 쿼리를 사용하여 SQL 인젝션 공격을 방지해야 합니다.

## 문제 3: 로그인 정보의 직접 출력
- **Severity:** Medium
- **시나리오:** `login` 함수 내부에서 사용자 이름과 비밀번호가 프린트됩니다. 이는 보안상 문제가 될 수 있으며, 특히 개발 환경에서는 민감한 정보가 노출될 위험이 있습니다.
- **수정 방향:** 로그인 시스템은 사용자의 입력을 출력하지 않도록 설계되어야 합니다.

## 문제 4: 권한 관리 부재
- **Severity:** Medium
- **시나리오:** `login` 함수에서 사용자 이름과 비밀번호가 일치하면 바로 해당 사용자의 역할 정보를 반환합니다. 이는 사용자가 자신의 역할을 변경하거나 다른 사용자의 역할 정보에 접근하는 것을 막지 못합니다.
- **수정 방향:** 권한 관리를 위한 추가적인 보안 메커니즘을 구현해야 합니다.
